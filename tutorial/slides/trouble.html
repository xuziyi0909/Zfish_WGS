When something goes wrong

Most problems have a one-line fix

You seeDo this
Permission deniedRun chmod +x run_wgs.sh once
MISSING a programSend the ./run_wgs.sh --check output to the server administrator
missing column or file not foundTabs, not spaces; paths start with data/raw/; no spaces in file names
The pipeline stoppedOpen the log it names, find “Error in rule”, fix it, run again
No space left on deviceFree space: each sample needs about 3× its FASTQ size
Directory cannot be lockedAnother run is going, or one crashed: see the unlock command in the guide
Run stopped when I logged outStart it inside screen, then just run ./run_wgs.sh again

These are the problems people actually hit. Almost all are fixed in one line. The general rule when the pipeline stops: open the log file it names, search for Error in rule, and read the last lines of the detailed log listed under it. After fixing, simply run the same command again; finished steps are not repeated. The troubleshooting page in the guide has the exact unlock command and more cases.
