The math · Calling a genotype

Which genotype best explains the reads?

n reads, k of them show the new letter T, each letter wrong with chance ε (Q30: ε = 0.001)

P(reads | CC) = (ε/3)k (1 − ε)n−k
P(reads | CT) = (½)n
P(reads | TT) = (1 − ε)k (ε/3)n−k

CT: each read comes from either copy, a coin flip. An error gives any of 3 other letters: ε/3. bcftools weighs the three with a prior (about 1 position in 1,000 differs) and reports the most likely.

QUAL = −10 log10 P(no sample has T | reads)

The weak spot at 3× coverage: a heterozygote shows only T in (½)n of cases, 1 in 8 with 3 reads and 1 in 32 with 5. Some “homozygous” calls are really one copy.

Here is how a genotype is decided. Take one position with n reads, k of them showing the new letter. For each possible genotype we ask how likely these reads would be. If the sample is CC, every T must be a sequencing error, so the chance is epsilon over three to the power k, tiny; the three is because an error can produce any of the three other letters. If it is TT, every C must be an error. If it is CT, each read comes from one of the two copies at random, like a coin flip, so any particular set of reads has chance one half to the power n. For the tmppe mutant, five T reads: CC is essentially impossible, CT has a chance of one in thirty-two, TT almost one. So the call is homozygous, with about 97 percent confidence. For the sibling, six C reads, the call is CC with about 98 percent. bcftools also adds a prior, the expectation that only about one position in a thousand differs, and uses each letter's own quality. QUAL is the Phred-scaled chance that no sample carries the variant. The key lesson: at low coverage, a heterozygote can look homozygous by chance, one time in eight with three reads.
